# Bytepay — AI Governance Deliverables

**A synthetic case study in AI governance, risk assessment and policy design.**

> **Disclosure:** Bytepay is a fictional organisation created for portfolio purposes. All systems, figures, risks and departmental structures described here are illustrative. This repository demonstrates governance methodology and documentation practice, not work performed for a real client.

---

## Purpose

This repository holds the governance artefacts produced for the Bytepay case study, kept under version control so that changes to each document are visible and traceable. Governance work is only credible if it can be shown to be maintained, so this repository is the living record rather than a static set of files.

## Deliverables

| # | Deliverable | Description | Status |
|---|---|---|---|
| 1 | Risk assessment register | Risk register with likelihood, impact, risk rating, treatment strategy, owner and residual risk | Pending upload |
| 2 | AI governance policy | Bytepay's governing policy for the responsible development and use of AI | Pending upload |
| 3 | Departmental roles and responsibilities | RACI-style allocation of AI governance accountabilities across departments | Pending upload |
| 4 | Project executive summary | One-page summary of the governance programme, scope and outcomes | Pending upload |

Each deliverable is provided in two forms where applicable: a PDF for reading, and an editable source file (`.xlsx` or `.md`) so the working document can be inspected.

## Frameworks referenced

- NIST AI Risk Management Framework (AI RMF 1.0)
- ISO/IEC 42001 — AI management systems
- EU AI Act — risk classification and obligations
- OECD AI Principles

## Change control

Every revision to a deliverable is recorded in `CHANGELOG.md` with a date and a short description of what changed and why. Superseded versions remain in the commit history rather than being overwritten silently.
